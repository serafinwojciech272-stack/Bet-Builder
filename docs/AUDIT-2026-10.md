## 1. TL;DR

1. **CI nie działa z dwóch niezależnych powodów.** (a) Wszystkie 3 workflowy (także `Production Daily Coupon E2E`, który zaczyna od `sleep 150`) padają po 1–3 s, czyli joby w ogóle nie startują. To jest blokada konta GitHub Actions (billing / spending limit / zablokowane Actions), a nie kod. (b) Nawet po odblokowaniu `npm run lint` pada na `no-empty` w `api/decision-reasoning.ts`. Tego nie naprawia też PR #53. **Naprawione na branchu.**
2. **Najpoważniejszy problem jest produktowy, nie techniczny: EV pokazywane użytkownikowi było fikcyjne.**
   - Feedy live dają drużynom `rating: 0.5` i puste `form`, więc model ratingowy sprowadza się do samej przewagi własnego boiska. *Każdy* gospodarz w piłce dostaje ~43% na wygraną, np. Lechia u siebie z Realem Madryt. To daje +300–400% „value” na każdym słabym gospodarzu.
   - `dailyCoupon.ts` liczył `modelProbability = implied × (1 + bonus za liczbę bukmacherów)`, czyli **każdy kurs miał dodatnie EV z definicji**. Kupon „STS + Superbet” promował więc longshoty na podstawie wymyślonej przewagi.
   - **Naprawione na branchu:** prawdopodobieństwo jest kotwiczone do konsensusu rynku po usunięciu marży (de-vig), a dodatnie EV oznacza teraz wyłącznie „kurs powyżej konsensusu bukmacherów”.
3. **Publiczne endpointy wydają Twoje pieniądze bez żadnej kontroli.** `/api/core-engine` (LLM przez Core Engine z serwerowym kluczem), `/api/odds` (płatne quota z sumowaniem `markets × regions` od klienta), `/api/research` i `/api/daily-coupon` nie mają auth ani rate limitu. Wystarczy pętla `curl`, żeby wyczerpać quota albo nabić rachunek. `/api/core-engine` przekazywał też *dowolną* akcję do `/api/mission`. **Częściowo naprawione** (rate limit, allowlisty, limity rozmiaru). Pełna naprawa wymaga auth użytkowników (roadmapa F2).
4. **„Milestone theatre”: 34 z ~72 modułów `src/core` nie są używane w produkcji, tylko w testach.** Chodzi o M101–M190: walk-forward backtest, model drift, champion/challenger, CLV, track record, devig itd. Commity deklarują „production certification”, a działający produkt z tego nie korzysta. Ironia: `marketDevig.ts`, czyli jedyny moduł, który rozwiązywał problem z pkt 2, był martwy.
5. **Nikt nie sprawdza typów w `api/` i `server.ts`.** `tsconfig` obejmuje tylko `src/`, a `api/` ma istniejące błędy typów. Backend uruchamia się przez `npx --yes tsx@4.19.4` przy *każdym* starcie (pobieranie z sieci przy cold starcie Render, ryzyko supply-chain).

## 4. Blueprint (stan docelowy)

### Pozycjonowanie
Bet Builder nie ma (i nie będzie miał bez danych historycznych) modelu przewidującego wyniki lepiej niż rynek. Uczciwy i sprzedawalny rdzeń to:
**line shopping + konsensus rynku + śledzenie CLV + dyscyplina decyzji (human gate, limity, dziennik).**
Model własny wchodzi dopiero wtedy, gdy *udowodni* na danych dodatni CLV (moduły champion/challenger już istnieją, tylko są martwe).

### Architektura

```
Browser (Vite SPA, static on Vercel/Render)
   │  one origin: /api/*
   ▼
API (Node, Render, server.ts) ── auth (Supabase JWT) ── rate limit / quota (Redis/Upstash)
   ├─ providers/      OddsProvider interface: sportsgameodds | parlay | the-odds-api | odds-api.io | sportscore*
   │                  + response cache (TTL 30–60 s) + quota ledger
   ├─ pricing/        devig consensus, best price, line movement, CLV   ← marketDevig, closingLineBenchmark
   ├─ coupon/         daily coupon, correlation, staking caps
   ├─ research/       news RSS (rate-limited, cached per event)
   ├─ ai-gateway/     Core Engine proxy: auth + per-user token budget + prompt hardening
   └─ persistence/    Supabase: odds_snapshots, decisions, outcomes, audit (RLS)
Jobs (Render cron)    snapshot collector (closing lines) → outcomes settler → CLV/track record
```

Zasady:
1. **Jeden runtime API.** Vercel serwuje tylko statyczne pliki + `rewrites` (cały katalog `api/` w `.vercelignore`) albo jest wyłączony. Żadnych funkcji zdublowanych z Render.
2. **Każdy endpoint wydający pieniądze** ma: auth (albo twardy limit anonimowy), rate limit we wspólnym store, cache, budżet dzienny i metrykę kosztu.
3. **Prawdopodobieństwo ma źródło** (`team-model` | `market-consensus`) i UI je pokazuje. Brak źródła oznacza brak EV.
4. **Historia kursów jest zapisywana.** Bez snapshotów zamknięcia nie ma CLV, backtestu ani sensu dla modułów M101+.
5. **Kod czytelny dla człowieka:** prettier, max-len, typecheck całego repo w CI.

```powershell
cd C:\path\to\Bet-Builder
git fetch origin
```
